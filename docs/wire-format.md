# MoonLatency 二进制格式 v1

下表中的整数字段使用大端序。计数和标识符的有效范围为 0 至 Int64.max。
版本号包含在四字节 ASCII 标识里。不同延迟单位的摘要应分别汇总。

| 标识 | 首部 | 记录 |
| --- | --- | --- |
| MLH1 | 标识 | u16 桶号、i64 正计数 |
| MLS1 | 标识、u8 单位、i64 来源、i64 序号、i64 时间戳 | 一个完整 MLH1 |
| MLS2 | MLS1 首部中的标识换为 MLS2，时间戳后增加 i64 正桶宽 | 一个完整 MLH1 |
| MLB1 | 标识、u16 分片数 | u16 字节长度、一个完整 MLS1 或 MLS2 |
| MLJ1 | 标识 | u32 批次长度、一个完整 MLB1、u32 CRC-32 |
| MLC1 | 标识、u8 单位、i64 桶宽、i64 最新桶号、u16 槽数、u16 身份容量、u16 分片数 | u16 长度、一个完整 MLS1 或 MLS2 |
| MLR1 | 标识、u16 服务容量、u16 服务数 | u8 名称字节长度、ASCII 名称、u32 检查点长度、一个完整 MLC1 |

- 单位编码 0 表示纳秒，1 表示微秒，2 表示毫秒。时间戳和桶宽由调用方约定公共时间轴。
- MLH1 省略空桶，按桶号递增，最多 960 条。空直方图只有标识。所有桶计数之和不得超过 Int64.max。
- MLS1 以接收方窗口的宽度归属时间桶。去重键是来源与序号，存活期间重新发送同一内容会被识别为重复。
- MLS2 的时间戳必须按声明的桶宽对齐。覆盖范围从该时间戳开始，到下一桶之前为止，并受 Int64 时间轴上限约束。接收端仅接收覆盖范围完整落在一个接收桶内的分片。
- MLB1 最多 1,024 片，空批次合法。整批按文件顺序应用，任意记录被拒绝都会回滚整个批次。
- MLJ1 使用 IEEE CRC-32，只覆盖批次字节。重放遇到坏帧会报错，先前成功的批次仍然生效。
- MLC1 的最新桶号为 -1 时表示尚未开始，分片数必须为 0。恢复会重新验证单位、窗口和去重状态。
- MLR1 按服务名递增。恢复受服务数量和总容量限制，并检查每个内嵌快照。

跨实现样例和 CRC 对照见 `scripts/check_collect.py`。
